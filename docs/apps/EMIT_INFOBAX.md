# 独立 InfoBAX 发射度优化

此版本保存已验证的独立原型作为重构检查点。正式框架接入采用现有发射度优化窗口内的 InfoBAX 标签页，并复用现有测量服务；标签页接入尚未实现。

独立入口复用 HALF 的螺线管电流控制、扫描四极铁读回确认和束矩重建。
默认使用 Fake 后端；导入模块或打开窗口不读写 PV。

## 启动与首轮配置

在 `feature/emit-infobax-integration` 工作区根目录运行：

```bash
bash scripts/run_emit_infobax.sh
```

选定一个现有测量预置、一个上游螺线管、X/Y 目标平面，以及电流范围、K1 扫描范围和能量。
电流范围必须包含实际初始设定值；5 个候选点由等距网格替换最近节点为初始值生成。
真机候选间距必须大于两倍电流读回容差（默认容差 0.01 A）。
profile 的设备目录顺序并非纵向位置；现有模型没有完整描述螺线管位置，操作员必须确认所选螺线管位于扫描段上游。

窗口默认使用 `transport_moments` 后验，也可选 M0 对照。核心 `InfoBAXCore` 原有默认仍为 M0。
ROI 留空时使用 profile 的图像 ROI；显式 ROI 为翻转后图像的 `left,right,bottom,top` 像素边界，右/上边界不包含在内。
背景为同一翻转方向、完整图像尺寸的 `.npy`，会冻结并保存到运行目录。留空表示不扣背景。

无界面离线检查需明确批准模拟操作：

```bash
bash scripts/run_emit_infobax.sh --headless --approve-fake --quick --run-root /tmp/emit-infobax-smoke
```

`--quick` 仅降低 Fake 检查的蒙特卡洛样本数，不评价算法效果。无界面入口禁止 real 后端。
Fake 使用合成束矩观测验证会话；相机统计和实际 CA 读写由单元测试及下述隔离 IOC 检查验证。

## 测量和操作流程

1. 启动后冻结设备、模型和相机设置，保存初始状态。操作员确认整批基线扫描。
2. 在初始电流完整扫描预置中的 K1 点。每个点默认使用 5 个独立新帧，最少 3 帧。
3. 基线束矩重建必须物理有效。基线观测直接进入模型，逐 K1 标准误复制到各候选作为固定预测噪声。
4. 在最低/最高电流工作点分别补 3 个 K1 初始化点。K1 由列归一化传输设计矩阵的 QR 主元选择；重复查询复用已有观测。每个建议单独确认。
5. 最多执行 3 个主动 InfoBAX 查询，每个建议单独确认；负 EIG 或无有效推荐会结束并还原。
6. 对最终推荐做一次独立完整扫描，由操作员确认整批执行。复核物理有效且目标发射度低于基线时，才启用“应用验证结果”。
7. 会话完成默认还原初始螺线管电流和扫描四极铁状态。应用结果需要再次确认，只改变螺线管电流。

图像沿用非负背景扣除约定，RMS 使用像素中心坐标。每帧强度二阶矩的均值作为观测，逐帧方差的样本标准差除以帧数平方根作为观测标准误。
Gaussian 使用同一批图像旁路记录，不决定模型输入。无信号、目标平面质量不合格、帧不足、零/无效标准误或曝光改变都会停止并还原；不自动重测、补噪声或放宽物理判据。
现场 ADU 不套用 VM 的粒子计数噪声系数。

默认学习上限为 `基线点数 + 最多 6 个初始化点 + 最多 3 个主动点`；最终复核单独记账。
以 15 点基线、3 个主动查询和 5 帧/点为例，最多 39 个测量点、195 个有效帧，另计每点丢弃的新帧。
120 分钟默认会话时限包含人工等待，恢复会话累计已用时间。

等待确认时保持上个已确认状态，不写磁铁。暂停、停止、超时和异常均尝试还原所有设备；一个设备失败不会跳过另一个。
还原失败禁止应用结果，可使用“恢复初始”重试。暂停可继续；中断进程的运行载入后须先恢复初始，再继续。
恢复时验证配置/模型/候选池指纹及实际初始状态，历史待确认建议不自动执行。

普通发射度扫描、原有完整扫描优化和本入口使用同一机器/后端控制锁。内部扫描借用外层会话租约。
该锁协调本仓库的这些入口，不覆盖外部控制软件或其他手动设备操作；每次确认执行及采集前后还会核对读回。

## 真机现场准备

```bash
bash scripts/run_emit_infobax.sh --backend real
```

当前 HALF profile 尚未提供经过核实的相机帧标识，真机开始按钮因此默认不可用。
部署时需要只读核实图像插件的帧标识与 `ArrayData` 的关联，不能仅选相机采集计数器或猜测 PV 名称。

核实后在相应屏的原生通道声明及 real 后端映射中增加逻辑通道 `frame_id`，保留现有 image/exposure 映射，
并在发射度 workflow 配置中声明已验证的屏。例如以下仅为配置结构，不含可直接使用的现场 PV：

```json
{
  "infobax_camera": {
    "PRF07": {"frame_id_matches_image": true}
  }
}
```

声明的前提是现场确认：稳定期间 frame ID 不倒退，ID 与发布的图像缓存对应，ID/image/ID 读取一致时可识别完整帧。
采样在磁铁稳定后建立 ID 屏障，丢弃首个新帧，再读取不同 ID 的后续帧；重复 ID 不作为独立样本，计数器回退会失败。
需结合实际曝光和传输缓冲延迟确认这一屏障有效。无法验证时维持禁用。
不修改 IOC DB 或自动生成的 VM/IOC 文件。

现场先验证通道、图像尺寸/ROI/背景、曝光、新帧、读回和还原，再开展逐条确认的小规模闭环。
传输束矩 GP 未强制束矩正定，INVALID 判据保持有效。工程链路通过与获得优化收益分别验收；现场结果尚未验证。
首版只优化单平面单螺线管，不提供电荷保持或另一平面的硬约束。

## 归档、接口与验证

运行目录默认在启动目录的 `runtime/emit_infobax/` 下，亦可用 `--run-root` 指定。
`infobax_workflow.json` 原子保存配置、模型快照、初始状态、建议意图、点统计、检查点、复核与操作记录。
原始帧在 `frames/*.npz`，包含帧 ID、曝光及原始数组；相机计数包含实际读取、不稳定读取、丢弃和接受帧数。
不合格帧也在分析前归档。另保存冻结背景。文件锁防止同一运行目录被并发或过期实例覆盖。

主要接口：

- `InfoBAXCore(..., model="M0", initial_queries=None)`；`propose(check=...)` 支持候选评估之间检查取消/时限。
- 默认 M0 自动初始化继续生成 v1 检查点；新模型/显式初始化使用包含模型和初始化索引的 v2 检查点。
- `HalfRealInfoBAXMachine` 实现现有单点机器协议；`CameraPointAcquirer` 返回已有 `PointMeasurement`。
- `InfoBAXWorkflow` 管理整条流程；`approve(request, check)` 必须可取消，缺省回调不批准执行。

离线与隔离 IOC 验证：

```bash
python3 -m unittest discover -s tests -p 'test_emit_infobax_standalone*.py' -q
python3 -m unittest discover -s tests -p 'test_infobax_core.py' -q
python3 scripts/check_emit_infobax_standalone_ioc.py --output /tmp/emit-infobax-ioc
bash scripts/check.sh
```

隔离检查启动有时限的私有 loopback softIOC，使用随机 `INFOBAX_TEST_...` 前缀并关闭地址发现。
其供电读回及相机由测试模拟，验证真实 Channel Access、相机采样、16 点闭环、8 次确认、80 个有效帧及设备还原；不运行 elegant，不连接现场 PV。
