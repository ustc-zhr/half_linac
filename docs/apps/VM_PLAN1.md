# HALF Linac VM 第一版提升计划

## 目标与分支

将现有启动配置界面升级为可观察束流状态的 VM 工作台，保留原有操作能力。全部界面文案、提示、图例使用英文，延续 HALF Linac 的明暗主题；参考图仅用于布局与交互借鉴。

当前分支为 `main`，工作区干净。实施第一步创建 `feat/vm-workbench-v1`；计划阶段尚未创建。

第一版覆盖 HALF、IRFEL 共用界面，继续使用 PyQt5、Matplotlib 和 Elegant。交付重点是二维束线、计算结果展示和可信状态反馈。

## 界面与操作

- **顶部状态栏**：机器名、当前线路、`IOC Status`、`Simulation Status`、最近成功计算时间与耗时。保留 `Start softIOC`、`Start VM`、`Stop Session` 和主题切换。
- **二维束线总览**：沿纵向位置展示当前 usedline 元件，支持滚动、缩放、点击选择；选中元件同时定位设备列表与曲线标记。重复出现的元件按线路中的出现位置区分。
- **左侧配置区**：使用 `Devices`、`Beam Source`、`Lattice`、`Errors` 分页。设备页提供搜索、类型、位置及模型参数只读查看；其余分页迁移现有功能，保留局部段束源交接限制。
- **中央曲线区**：提供 `Orbit`、`Twiss`、`Dispersion`、`Beam Size` 切换，显示横纵平面数据及单位，支持缩放与恢复视图。默认显示 `Orbit`。
- **右侧诊断区**：独立选择当前线路中可用的屏幕 WATCH，显示横向二维粒子分布、质心及 RMS 尺寸。诊断选择不随磁铁选择改变；没有数据时显示原因。
- **底部反馈区**：常驻简短状态，日志默认折叠，错误时显示可展开提示。布局可拖动调整，在 1366×768 窗口内保持主要操作可用。

第一版继续通过原有束源、线路和误差操作修改模型。元件直接编辑、滑块调参、基线比较、工作点保存载入、扫描和 3D 展示留到下一版。

## 后端与结果一致性

- 在共享 VM GUI 与运行循环之间增加独立的运行状态文件，记录会话、计算编号、输入版本、阶段、耗时、错误和诊断发布结果；原子更新，避免读取半写入状态。
- `Ready` 必须来自成功完成的计算，取消“进程存活两秒即就绪”的判断。IOC 主管进程运行与实际 IOC 就绪分别表达；没有明确就绪证据时显示 `Process Running`。
- 每轮计算使用冻结的运行 JSON 快照生成输入，以内容摘要识别版本。计算期间收到新设置后排队处理最新版本；旧结果不能标成当前设置的结果。
- 计算成功后生成独立结果快照供 GUI 读取，避免 GUI 与下一轮 Elegant 同时读取、覆盖同一批输出。计算成功和 PV 发布成功分别显示，发布不完整时明确标为警告。
- 新增只读结果适配层，从 SDDS 按列名读取轨道、Twiss、色散、粒子 RMS 尺寸及 WATCH 粒子数据，统一单位。缺少输出或列时对应视图显示 `Unavailable`，不填零、不以 Twiss 推算结果冒充粒子 RMS。
- 在生成 Elegant 控制文件时启用所需的 sigma 输出，不手工修改生成文件。新增状态和结果文件不加入 JSON 输入监听，不触发额外计算，也不纳入源码。
- GUI 异步加载结果并在完整读取后刷新视图；输入变化或计算失败时保留上一轮图像，并显示 `Out of Date` 或 `Last Successful Result`。
- 接入子进程输出和退出状态，启动、停止过程不阻塞 GUI。修复误差脚本吞异常并返回成功的问题；误差参数先验证，再一次性更新运行状态。

这些改动保持现有 PV 命名、IOC DB 和诊断发布映射不变；新增数据用于 GUI 观察，不新增 PV 写入入口。GUI 关闭时继续只停止本窗口启动的进程。

## 验证与验收

- 使用离线样本验证 SDDS 列解析、单位、重复元件定位，以及空数据、缺失输出、读取失败的反馈。
- 使用模拟子进程验证：启动失败、计算失败、发布部分失败、运行中输入变化、旧会话状态遗留和停止超时。
- 验证 HALF、IRFEL 两种配置，以及完整线路、预定义线路、局部段切换；保留束源和误差设置原有功能。
- 离屏检查英文文案、明暗主题、窗口缩放、设备与曲线联动、独立诊断选择及日志展开。
- 执行 `python3 -m compileall src/virtual_machine` 和 `bash scripts/check.sh`。真实 Elegant／IOC 联调列为手动验收，不在默认验证中启动长运行进程。

验收标准：用户可以在一个窗口完成现有 VM 配置操作，看到与输入版本对应的束流结果，并明确区分“正在运行、正在计算、计算成功、结果过期、发布失败”。界面保持全英文，主视图优先展示束流，配置与日志按需展开。
