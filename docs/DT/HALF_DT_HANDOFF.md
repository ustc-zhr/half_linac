## 1. 项目背景与定位

### 1.1 当前基础

HALF 注入器已经完成直线加速器部分的初期 commissioning，现有 `half_linac` 是 Python 上层调束软件，具有机器设备接口、GUI、任务状态机、自动调束流程和数据采集分析等功能。

相关已讨论能力包括：

- RF 相位及 RF timing 扫描。
- BBA 批量调束。
- 发射度测量相关自动化。
- 与 GOTAcc 在线智能优化的协作。
- 对真实 EPICS PV 的访问和设备操作。

这些功能可以作为未来虚拟加速器、数字影子和智能调束的上层基础。

同时，已有初步的分段虚拟加速器研究：

- 预注入器：使用 Windows 版 PARMELA。
- 高能段：已研究并验证过 Cheetah 与 ELEGANT 在不考虑尾场、CSR 等效应时的部分一致性。
- NN 预注入器代理模型已纳入技术路线，但其新的模型结构和训练流程尚未完成验证。

以上为此前研究基础，并非本次 IMPACT-T 新方案的实施完成情况。

### 1.2 数字孪生的定位

此前重点分析 JANUS/CLARA 等工作，得到以下认识：

**虚拟加速器（Virtual Accelerator）**

具备束流物理模拟、设备参数设置、诊断预测等能力，但不一定与真实机器持续同步。

**数字影子（Digital Shadow）**

在虚拟加速器基础上读取真实设备状态，能够反映真实机器的部分运行状态，但尚未具备可靠的持续自动校准。

**在线校准数字影子（Online-calibrated Digital Shadow）**

具备真机状态同步、模型参数辨识、预测残差监测和模型更新能力。

**数字孪生（Digital Twin）**

进一步将持续同步、模型校准、预测及辅助决策或受控闭环调束结合起来。

JANUS 在机器描述自动生成、跨装置实例、多物理引擎管理、虚拟控制接口及部署方面具有工程优势，但现有论文证据不足以证明其已经实现完整意义上的持续在线校准及自主闭环数字孪生。

因此，HALF 不需要为了宣称数字孪生而过早开发复杂的自动闭环。

近期明确定位为：

**面向 HALF 注入器的多引擎快速虚拟加速器，并逐步扩展为具备真机状态同步和在线模型校准能力的数字影子。**

长期目标是服务于模型辅助调束、在线优化、可微束流动力学及自主调束。

## 2. 已确定的核心技术决策

### 决策 D1：采用物理模型 + 快速代理模型

不是直接用 NN 完全替换物理模型，而是建立：

- 高保真物理模型：用于基准计算、参数扫描、物理校验和训练数据生成。
- 快速 NN 代理模型：用于实时交互、优化、灵敏度计算和快速预测。
- 跨引擎接口：保证两种模型均可向下游提供一致定义的束流状态。

### 决策 D2：预注入器全部由 IMPACT-T 建模

**明确的物理范围：从热阴极电子发射到 L01B 加速管出口。**

原 PARMELA 仅作为已有物理参考和迁移验证基准，不再作为目标 Linux 运行环境中的主要在线物理引擎。

采用 IMPACT-T 的主要原因：

1. 支持 Linux 运行环境。
2. 支持时间域粒子追踪和三维空间电荷计算。
3. 具有外部电磁场输入能力。
4. 可通过 Python 工具进行自动化调用。
5. 适合生成 NN 代理模型所需的大规模数据集。

候选软件组件：

- IMPACT-T
- LUME-Impact
- openPMD-beamphysics
- Python / PyTorch

注意：尚未在 WSL 中实际完成安装或验证。软件版本、场图格式、发射模型和粒子数据格式必须以实际运行结果为准。

### 决策 D3：L01B 出口为统一模型交接截面

完整建模链条：

```text
HALF machine settings / PVs
           |
           v
    Parameter Mapping
           |
           v
   Pre-injector Engine
   Cathode -> L01B exit
           |
     +-----+-----+
     |           |
  IMPACT-T    NN Surrogate
     |           |
     +-----+-----+
           |
           v
    L01B Beam Interface
    6D distribution/state
           |
           v
         Cheetah
           |
           v
    Downstream LINAC
           |
           v
   Virtual Diagnostics
```

这只是逻辑架构。IMPACT-T 与 NN 为可切换后端，不要求每次仿真同时运行。

L01B 出口还应设计为统一的数据接口，包含：

- 六维粒子分布或统计束流状态。
- 参考粒子能量及动量。
- 束团电荷、粒子权重、粒子损失信息。
- 时间坐标和参考 RF 相位约定。
- 坐标系、单位、束流方向等元数据。
- 模型运行配置、版本和输入参数快照。

**必须明确：L01B 出口是软件接口选择，不代表已经证明 Cheetah 在该处能完整处理所有剩余空间电荷或集体效应。**

后续应通过重叠区计算验证分界面的物理合理性。

### 决策 D4：近期优先实现固定的多引擎链

第一阶段不追求 JANUS 式任意机器描述自动生成，也不追求复杂的分布式引擎调度。

只实现：

```text
IMPACT-T ─┐
          ├─ Beam Interface ─ Cheetah
NN ───────┘
```

以及所需的：

- 引擎选择。
- 参数传递。
- 运行状态管理。
- 模型依赖与重算。
- 结果缓存与失效。
- 异常处理。
- 数据版本及结果追溯。

这是近期最有实际价值的多引擎编排范围。

## 3. IMPACT-T 预注入器模型

### 3.1 需要覆盖的物理过程

从阴极到 L01B 出口，需要考虑：

1. 热阴极电子发射。
2. 栅控电子束流的时间结构。
3. 阴极至阳极的直流静电加速。
4. 低能区空间电荷作用。
5. 后续聚焦元件。
6. PB 的纵向 RF 调制。
7. L01A、L01B 的加速及 RF 相关效应。
8. 横向与纵向束流动力学的耦合。

具体元件顺序、实际位置和元件场图，必须从当前 PARMELA 文件及 HALF 设备资料中提取，不应直接依据此摘要生成最终 lattice。

### 3.2 热阴极栅控直流枪是最重要的迁移风险

现有 PARMELA 模型：

- 模拟热阴极栅控直流高压电子枪。
- 当前没有显式考虑栅网结构。
- 使用等效发射分布及静电场。
- 已经讨论过 `RUN`、`INPUT` 和 `CATHODE` 模式下初始能量及温度参数的物理含义。

目标是在 IMPACT-T 中保留相同或更合理的物理描述。

需要特别区分：

**热发射模型**

决定阴极处电子初始能量与角分布、空间分布和热发射度。

**栅控发射模型**

决定发射电流随时间的变化及电子束微观纵向结构。

**静电加速模型**

决定阴极—阳极之间的轨迹、加速、聚焦和空间电荷演化。

不能简单认为 IMPACT-T 内置的光阴极发射功能就等价于热阴极栅控发射。

需要核查当前 IMPACT-T 版本是否具备所需的发射时间初始化、静电场追踪及外部粒子输入能力；必要时使用自定义初始分布或扩展模型。

### 3.3 建议的物理验证截面

在同一个 IMPACT-T 全段模型中设置检查点：

| 截面 | 关键比较量 |
|---|---|
| 直流枪出口 | 能量、束斑、发射度、纵向分布 |
| PB 出口 | 束长、能量调制、横纵向分布 |
| L01B 出口 | 六维分布、能量、能散、发射度、束长 |

准确的截面坐标应根据原始设备模型确定。

### 3.4 与 PARMELA 比较

至少执行：

- 相同初始电子分布下的追踪比较。
- 关闭空间电荷时的基准比较。
- 打开空间电荷后的比较。
- 直流枪高压扫描。
- PB 幅相扫描。
- 加速 RF 相位与幅度扫描。
- 螺线管参数扫描。
- 宏粒子数、网格、时间步长收敛性测试。

需要同时比较标量束流指标和完整相空间结构。

不能在未比较的情况下假定 IMPACT-T 与 PARMELA 理应完全一致。

## 4. NN 代理模型路线

### 4.1 输入

NN 输入应基于真实独立可调物理参数和必要的初始束流状态，例如：

```text
Gun HV / emission parameters
PB amplitude / phase
RF amplitude / phase
RF timing
Solenoid current / field
Initial beam conditions
```

最终参数清单需要由原 PARMELA 模型、设备布局和实际 PV 映射表确定。

需要注意：

**真实设备控制变量不一定等于模型中的独立物理变量。**

例如 HALF 的 PB、L01A 和 L01B 涉及共用 RF 功率源与相位关系，不能简单假设所有腔体幅相都可以独立任意变化。

### 4.2 NN 作为完整预注入器代理

模型形式：

\[
\mathbf B_{\mathrm{L01B}}
=f_{\mathrm{NN}}(\mathbf u)
\]

其中输入 \(\mathbf u\) 为机器可调参数和必要的初始束流条件，输出为 L01B 出口束流状态。

此前比较了三种代理表示。

**方案 A：直接预测标量指标**

例如能量、能散、束长、发射度、束斑、电荷。

适用于简单优化，但不足以唯一确定下游束流动力学。

**方案 B：预测六维统计束流状态**

预测六维均值、协方差矩阵、参考能量及电荷。

这是当前推荐的第一版方案。

输出能够与 Cheetah 的统计束流表示衔接，模型训练复杂度相对适中。

需保证预测协方差矩阵的物理一致性，例如使用适当的矩阵参数化。

**方案 C：预测完整六维粒子分布**

可使用条件生成模型（如 normalizing flow）学习非高斯六维相空间分布。

能够更完整保留纵向结构、尾部、非线性相关性及其他高阶特征，但数据与验证成本明显更高。

### 4.3 当前决策

**优先实现方案 B，保留升级到方案 C 的接口。**

同时保留 A 类标量指标作为训练、验证和真机诊断比较的重要输出。

应特别注意：统计束流代理不能自动保留非高斯分布、切片结构、束流损失及多束团效应。这些影响必须通过 IMPACT-T → Cheetah 的高保真参考计算评估。

### 4.4 训练数据

优先使用经过验证的 IMPACT-T 参数扫描数据。

推荐流程：

```text
Parameter Space Definition
           |
           v
      Sobol Sampling
           |
           v
      IMPACT-T Runs
           |
           v
   Particle Postprocessing
           |
           v
     Training Dataset
           |
           v
      NN Training
           |
           v
    Independent Testing
           |
           v
   NN -> Cheetah Testing
```

需保存完整的输入参数、仿真配置、随机种子、数值精度、模型版本、输出及失败记录。

应避免训练与验证数据因相邻扫描点、相同初始粒子随机实现等原因产生数据泄漏。

对低可信度预测和训练分布之外的输入，应具有检测和退回高保真模型的机制。

## 5. 真机参数映射与模型校准

### 5.1 参数映射是独立的架构层

不建议直接将 EPICS PV 数值等同于物理模型参数。

采用：

```text
EPICS PV
    |
    v
Device Calibration / Physics Mapping
    |
    v
Physical Model Parameters
    |
    v
IMPACT-T / NN / Cheetah
    |
    v
Predicted Diagnostics
```

映射关系包括：

- Magnet current → 磁场、聚焦强度。
- Solenoid current → 实际轴向磁场分布。
- RF setpoint → 有效 RF 场幅度。
- RF PV phase → 物理场相位。
- Modulator HV → 有效 RF 输出状态。
- Timing PV → 电子束与 RF 的相对到达时间。
- Gun setpoints → 初始电子束参数。

需要区分控制设定值、实际监测值、标定参数和不可直接观测的潜在状态。

### 5.2 HALF 特别需要注意的耦合

此前 commissioning 中已经观察到：

- 温度变化可能影响速调管输出状态。
- KLY01 功率输出存在饱和相关问题。
- PB、L01A、L01B 存在共用 RF 功率源及相关耦合。
- 预注入段的变化可能影响后续加速段与弯段的束流状态。
- 仅在下游校正能量，不一定能恢复预注入器内部的最佳工作点。

因此应优先建立 RF 幅相、高压、时序和设备实际场之间的物理映射，而非仅将 PV 输入 NN。

### 5.3 在线模型校准的原则

以后模型进入在线运行时，优先校准：

1. 有物理意义且可辨识的设备参数。
2. 标定系数、相位零点和有效场强。
3. 必要的初始束流潜在状态。
4. 小规模残差模型。

避免通过随意调整安装误差、RF 相位或其他物理参数来吸收缺失的空间电荷、尾场和 CSR 物理。

近期只做只读状态同步与残差比较，不允许虚拟模型直接向真机自动写入控制命令。

## 6. half_linac 多引擎编排

### 6.1 目标

half_linac 不应只是把两个模拟脚本顺序运行，而应提供统一的模拟服务。

建议具备如下逻辑接口：

```python
model = VirtualAccelerator(config)

model.sync_machine_state(snapshot)
model.set_parameters(parameters)

result = model.run(
    mode="high_fidelity"  # or "surrogate"
)

beam = result.beam_at("L01B_EXIT")
diagnostics = result.diagnostics
```

以上仅为建议的接口语义，并非已有仓库 API。

### 6.2 近期必须完成的功能

- 不同物理引擎的参数适配。
- 模型中间截面统一定义。
- IMPACT-T 与 NN 后端切换。
- L01B 出口束流状态到 Cheetah 的转换。
- 参数改变后的依赖重算。
- 输出缓存与缓存失效判断。
- 计算失败后的明确异常状态。
- 输入和结果的完整追溯。
- 模型与真实设备访问接口隔离。

跨引擎交换建议优先评估 openPMD-beamphysics 等已有工具，避免使用缺少元数据的临时数组格式。

### 6.3 与 GOTAcc 的关系

长期目标是让 GOTAcc 能使用同一套统一模型接口开展：

- 虚拟环境优化测试。
- 模型辅助 BO。
- 基于模型的初始工作点推荐。
- 安全约束与可行域预测。
- 真机在线优化。

但近期不应把 GOTAcc 集成作为 IMPACT-T 迁移的前置条件。

## 7. WSL 环境的实施路线

### P0：环境与基准模型

**目标：在 Linux 上启动可重复的 IMPACT-T 计算。**

任务：

1. 检查 WSL、Linux、Python、编译器和 MPI 环境。
2. 安装并验证 IMPACT-T。
3. 评估 LUME-Impact 的适配情况。
4. 收集 PARMELA 输入文件、场图及基准结果。
5. 建立原始输入文件清单与版本记录。
6. 建立最小 IMPACT-T 示例，验证静电场、RF 元件与空间电荷计算。

验收：有可重复的 IMPACT-T 计算结果及完整运行记录。

### P1：阴极至 L01B 全段物理模型

**目标：建立能够独立运行的全段 IMPACT-T 模型。**

任务：

1. 迁移直流枪静电场。
2. 构建热阴极等效发射分布。
3. 迁移聚焦元件、PB、L01A、L01B。
4. 建立统一纵向坐标和 RF 相位约定。
5. 与 PARMELA 在三个检查截面进行比较。
6. 开展空间电荷及数值收敛性研究。

验收：全段可运行，且关键差异已定量分析和解释。

不能预先指定未经物理验证的统一误差阈值。

### P2：IMPACT-T → Cheetah 接口

**目标：实现全段粒子追踪的跨引擎连接。**

任务：

1. 导出 L01B 出口六维粒子分布。
2. 定义统一粒子坐标及权重。
3. 转换为 Cheetah 可读取的束流状态。
4. 校验相空间统计量和束流方向。
5. 使用重叠追踪验证引擎切换造成的误差。

验收：相同输入能够进行可重复的串联计算。

### P3：NN 代理模型

**目标：建立可替代 IMPACT-T 快速运行的预注入器代理。**

任务：

1. 确定有效参数空间。
2. 自动生成 IMPACT-T 训练数据。
3. 建立六维统计状态代理模型。
4. 完成独立测试和不确定性分析。
5. 比较 NN → Cheetah 和 IMPACT-T → Cheetah 的预测。
6. 建立超出适用域时的处理机制。

验收：在约定参数范围内实现可接受的精度和明显的速度收益。

### P4：half_linac 集成与真机映射

**目标：实现可交互、可读取实际机器状态的虚拟加速器。**

任务：

1. 统一引擎接口。
2. 接入真实设备参数映射。
3. 建立机器快照机制。
4. 添加高保真与代理模型切换。
5. 支持只读模式下的实机诊断比较。
6. 逐步开展在线模型校准。

验收：能够以真实机器快照为输入，复现模型预测、诊断对比及结果追溯。
